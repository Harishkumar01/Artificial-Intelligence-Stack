# Remote Logs MCP — local SFTP, Windows

Six tools connect Codex to Oracle Linux 9.7 log directories through your existing VPN and SFTP service. No service installation on Oracle Linux is required. This release uses the MCP Python SDK v1 API, deliberately constrained below v2.

## Guarantees and scope

- Remote operations use only SFTP metadata/listing and file opens in `rb` mode. No shell, uploads, deletion, rename, chmod, or configuration tools are exposed.
- `download_file` is the sole tool with a local write side effect. It creates unique files only under the operator-configured local download directory; callers cannot choose a destination. Its MCP `readOnlyHint` is correctly false because it writes locally. The other five tools are marked read-only. Annotations describe behavior; code and account permissions enforce it.
- Configure a **read-only server account** for independent server enforcement. The MCP cannot remove write privileges from an existing username. Reads may update server access times or audit logs. This program does not constrain an agent's unrelated tools.
- Paths are relative to named approved roots. Parent traversal, absolute tool paths, non-regular file reads and symlinks below canonical roots are rejected. Because SFTP path checks and opens are separate operations, a hostile concurrent filesystem replacement cannot be ruled out atomically. Use server-side SFTP chroot/access controls if root confinement must withstand a hostile server filesystem. Keep configured root paths and their ancestors administrator-controlled.
- Passwords are Windows current-user DPAPI ciphertext inside the config. They can be decrypted only under the appropriate Windows account/machine context. DPAPI does not protect against another process already running as that same user. Restrict config directory ACLs and never commit the real config. Python necessarily holds plaintext briefly in process memory.
- Log output is untrusted data and can contain sensitive application data. Returned snippets enter your Codex chat; use only environments/data approved for that workflow. Passwords are not exposed by the tools.

## Install

Use Windows PowerShell with Python 3.11 or newer. In this package folder:

You can run `./Setup.ps1`, then `./Configure.ps1`, or use the equivalent commands below. Python 3.12 is the version verified for the supplied dependency lock. The lock also includes test dependencies. `Start.ps1` is an optional stdio launcher; MCP hosts should normally invoke the virtual environment's Python directly.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
```

The accompanying lock file records the versions used for verification. Do not copy `work/venv` from the development workspace.

## Configure each environment

1. Connect your VPN.
2. Obtain the SSH server's verified **OpenSSH public host key** from your administrator. A WinSCP fingerprint alone is not a `known_hosts` entry. If using `ssh-keyscan`, independently compare its fingerprint with the administrator/WinSCP record before trusting it; do not blindly accept scanned keys.
3. Place verified entries in a local `known_hosts` file. Example format: `192.0.2.10 ssh-ed25519 AAAA...`. For non-default ports use `[192.0.2.10]:2222` as the host field. Use the key actually supplied by your administrator.
4. Run the interactive setup, outside the agent:

```powershell
.\.venv\Scripts\python.exe -m remote_logs.configure --config .\config.json
```

Enter an environment alias, IP, port, username, known_hosts path, approved log roots, and password at the hidden prompt. Repeat for DEV/UAT/production as needed. Repeating an alias replaces that environment; other entries remain. The command never takes a password on its command line and never connects remotely. Actual credentials must not be sent in chat.

`config.example.json` documents the format but is not ready to connect. `password_dpapi` is generated by setup, not manually typed. Relative local paths resolve against the config file's directory. `download_directory` can be edited by the operator; its default is `downloads`. Restart the MCP after config changes. To rotate a password, rerun setup for that alias. Moving to a different Windows account/machine requires entering credentials again.

## Use PuTTY's cached host keys

PuTTY stores trusted public host keys under
`HKEY_CURRENT_USER\Software\SimonTatham\PuTTY\SshHostKeys`.
The MCP expects an OpenSSH-format file on local Windows, so convert the cached
keys using `Export-PuTTYHostKey.py`. Do not enter the registry path or a remote
Linux path as the `known_hosts` location.

During interactive configuration (`Configure.ps1`, after `Setup.ps1`), you can
**leave the known_hosts location blank and press Enter**. This selects
`known_hosts` beside `config.json`; it does not disable host-key verification.
You can finish configuration first, then create that file before connecting.
The scripts are named `Setup.ps1` and `Configure.ps1`, not `setup.ps2`.

Run the following in this package folder, using the same Windows account as
PuTTY. Replace the sample IP/port with the exact hostname/IP and port used in
PuTTY and in your environment's config:

```powershell
.\.venv\Scripts\python.exe .\Export-PuTTYHostKey.py --host 100.76.163.21 --port 22 --output .\known_hosts
```

The helper reads only the selected server's cached public keys. It does not
contact the server, modify the registry, or access passwords/private keys.
It exports the keys you have already trusted in PuTTY; it does not establish
their authenticity independently. It never overwrites an existing output file.
If `known_hosts` already exists, export to a new filename such as
`known_hosts-putty` and set that filename for the environment in `config.json`.

For the default output, the environment setting should be:

```json
"known_hosts": "known_hosts"
```

If no matching cached key is found, check whether PuTTY uses a hostname instead
of an IP address and use that same host in both the export command and config.
After creating the file or changing config, restart the MCP/Codex with VPN
connected, then ask it to list files in an approved log root.

## Connect your MCP host

Launch the following stdio command using absolute paths (replace `C:/path/remote-logs-mcp` with this package's location):

```json
{
  "mcpServers": {
    "remote-logs": {
      "command": "C:/path/remote-logs-mcp/.venv/Scripts/python.exe",
      "args": ["-m", "remote_logs.server", "--config", "C:/path/remote-logs-mcp/config.json"]
    }
  }
}
```

This is a generic MCP host JSON example; use your host's equivalent local stdio configuration. Nothing needs to listen on an HTTP port. Startup/protocol use stdout; do not add print statements to server code.

## Tools

| Tool | Main arguments | Behavior |
|---|---|---|
| `list_servers` | none | Environment and root aliases; no credentials |
| `list_directory` | environment, root, path, offset, limit | Navigate via explicit relative paths; up to 200 entries/page |
| `find_files` | environment, root, path, pattern, max_depth, limit | Filename glob, up to depth 8 and 200 matches |
| `read_log` | environment, root, path, offset, max_bytes, tail | UTF-8 byte window, up to 256,000 bytes; includes offsets |
| `search_logs` | environment, root, paths, text, case_sensitive, context_lines, limit | Literal search; returns line numbers and bounded surrounding text |
| `download_file` | environment, root, path | Unique local file with sanitized original filename, source path in result, SHA-256 |

Example prompt: “List the configured environments. In UAT's application root, find application logs, search app.log for ABC123, read the surrounding evidence, and explain the failure.” Use `read_log(tail=true)` for recent data when searching the first 8 MB is insufficient. Offset reads can split lines and UTF-8 characters; results use replacement decoding.

## Hard limits and current limitations

- Downloads must be **strictly below 100,000,000 bytes** (100 decimal MB). Equality is rejected before transfer. Growth to this boundary aborts the transfer and removes its partial file.
- Downloads have a 60-second total operation deadline, including connection setup. Other remote operations have 30 seconds. SSH connect/login each have 10-second limits. At most two remote operations run concurrently; further requests queue.
- Filename traversal examines at most 2,000 entries; directory listing collects at most 2,000 entries. Listings are capped, not complete inventories of larger directories. Offsets are best-effort across directory changes. Narrow the configured root/path for large directories.
- Content search transfers at most 8,000,000 bytes across 1–20 explicitly selected files, starting at each file's beginning. It is SFTP-only, so these bytes travel over the VPN. Maximum 100 matches and 64,000 text characters total; each context snippet is at most 8,000 characters. No regex, server grep, live tail sessions, or automatic reconnect/retry loops.
- Compressed logs can be downloaded within the limit but cannot be searched/decompressed by v1. No timestamp filtering or redaction is claimed.
- Reads/searches report observed size/mtime changes. Downloads discard changed copies. These checks detect common rotation/growth but are not atomic snapshots; metadata-preserving rewrites may go undetected. Prefer completed rotated logs.
- VPN is a prerequisite, not something this MCP starts or controls. Connection/authentication/host-key failures return a generic error without leaking credentials.
